## What it is

A search box that fetches results from a server while the user types. The naive version sends **one request per keystroke** ("r", "re", "rea", "reac"…), and slow responses can arrive out of order, so **old results overwrite new ones**.

## Standard vs optimized

<CodeTabs>
<Tab label="Standard">

```tsx
function Search() {
  const [q, setQ] = useState("");
  const [results, setResults] = useState<Item[]>([]);

  useEffect(() => {
    // ❌ Fires on every keystroke, no cancellation → race conditions
    fetch(`/api/search?q=${q}`)
      .then((r) => r.json())
      .then(setResults);
  }, [q]);

  return <input value={q} onChange={(e) => setQ(e.target.value)} />;
}
```

</Tab>
<Tab label="Optimized">

```tsx
function useDebounce<T>(value: T, delay = 300) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);
  }, [value, delay]);
  return debounced;
}

function Search() {
  const [q, setQ] = useState("");
  const debouncedQ = useDebounce(q.trim(), 300);
  const [results, setResults] = useState<Item[]>([]);
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    if (!debouncedQ) return setResults([]);
    const controller = new AbortController(); // ✅ cancel outdated requests
    setLoading(true);
    fetch(`/api/search?q=${encodeURIComponent(debouncedQ)}`, { signal: controller.signal })
      .then((r) => r.json())
      .then(setResults)
      .catch((e) => e.name !== "AbortError" && console.error(e))
      .finally(() => !controller.signal.aborted && setLoading(false));
    return () => controller.abort();
  }, [debouncedQ]);

  return (
    <>
      <input value={q} onChange={(e) => setQ(e.target.value)} placeholder="Search…" />
      {loading && <p>Searching…</p>}
      <ul>{results.map((r) => <li key={r.id}>{r.name}</li>)}</ul>
    </>
  );
}
```

</Tab>

<Callout type="why" title="Why it's better">
- **Debounce** waits until typing pauses (300 ms), so "react" makes 1 request instead of 5.
- **`AbortController`** cancels the previous request, so a slow old response can never replace newer results.
- **`encodeURIComponent`** stops spaces and `&` from breaking the URL.
- **SWR / React Query** also cache results: typing "react", deleting a letter and retyping it is instant.
</Callout>

## How to use

1. Copy the `useDebounce` hook into `hooks/useDebounce.ts`.
2. Debounce the **value**, not the `onChange` handler, so the input stays responsive.
3. Fetch inside `useEffect` with an `AbortController`, and abort in the cleanup.
4. Show a loading state and an empty state ("No results for …").
5. 250–400 ms is a good delay for search.

## Use-case demos

### Use case 1: Next.js route handler for the search API

```ts
// app/api/search/route.ts
import { NextResponse } from "next/server";
import { db } from "@/lib/db";

export async function GET(req: Request) {
  const q = new URL(req.url).searchParams.get("q")?.trim() ?? "";
  if (q.length < 2) return NextResponse.json([]);
  const items = await db.product.findMany({
    where: { name: { contains: q, mode: "insensitive" } },
    take: 10,
    select: { id: true, name: true },
  });
  return NextResponse.json(items);
}
```

### Use case 2: autocomplete with keyboard navigation

```tsx
const [active, setActive] = useState(-1);

function onKeyDown(e: React.KeyboardEvent) {
  if (e.key === "ArrowDown") setActive((i) => Math.min(i + 1, results.length - 1));
  if (e.key === "ArrowUp") setActive((i) => Math.max(i - 1, 0));
  if (e.key === "Enter" && results[active]) router.push(`/product/${results[active].id}`);
  if (e.key === "Escape") setResults([]);
}
```

## Pitfalls & when not to use

<Callout type="warn" title="Watch out">
- For **local** data (already in memory) you don't need debounce. Use [List Filtering](/react/list-filtering) with `useDeferredValue`.
- Set a minimum query length (2–3 chars) so you don't search the whole database for "a".
- In React Strict Mode (dev), effects run twice. The AbortController makes that harmless.
</Callout>

## Interview questions

<QA q="Why debounce a search input that calls an API?" level="junior">

Without it, every keystroke fires a request: typing 'react hooks' sends 11 requests, most of which are useless. That wastes server and network resources, can hit rate limits, and causes results to flicker. Debouncing waits until the user pauses (often 250 to 400 ms) and then sends one request for the final text.

</QA>

<QA q="What is a race condition in search-as-you-type, and how do you prevent it?" level="mid">

Responses can arrive out of order: the request for 're' might finish after the one for 'react', so the UI shows results for an older query. Debouncing reduces this but doesn't eliminate it. Fix it by aborting the previous request with an `AbortController` in the effect cleanup, or by ignoring responses that don't match the latest query. Libraries like SWR and TanStack Query key results by query, so stale responses never overwrite current ones.

</QA>

<QA q="Implement the core of a debounced search in React." level="mid">

Debounce the **value**, then fetch when the debounced value changes:

```tsx
const debounced = useDebouncedValue(query, 300);

useEffect(() => {
  if (debounced.length < 2) return;
  const controller = new AbortController();
  fetch(`/api/search?q=${encodeURIComponent(debounced)}`, { signal: controller.signal })
    .then((r) => r.json())
    .then(setResults)
    .catch((e) => { if (e.name !== "AbortError") setError(e); });
  return () => controller.abort();
}, [debounced]);
```

Key points to mention: encode the query, abort in cleanup, ignore `AbortError`, and enforce a minimum length.

</QA>

<QA q="What's wrong with this code?" level="mid">

```tsx
function Search() {
  const [q, setQ] = useState("");
  const search = debounce((v: string) => fetchResults(v), 300);
  return <input value={q} onChange={(e) => { setQ(e.target.value); search(e.target.value); }} />;
}
```

`debounce` creates a new function with its own timer on every render, and each keystroke causes a render, so every keystroke gets a fresh debounced function and nothing is actually debounced: all calls fire after 300 ms. Create it once with `useMemo`/`useRef` (and cancel it on unmount), or debounce the value with a `useDebouncedValue` hook as above.

</QA>

<QA q="Debounce vs useDeferredValue: which should you use for search?" level="senior">

They solve different problems. Debounce delays **work** (network requests) by a fixed time and reduces how many requests happen. `useDeferredValue` doesn't delay anything by time: it lets React render the urgent update (the input) first and render the expensive part with the deferred value in the background, interruptibly. Use debounce for API calls, and `useDeferredValue` for filtering data that's already in memory. See [List Filtering](/react/list-filtering).

</QA>

<QA q="How would you make the search UX feel fast and robust?" level="senior">

Show a subtle loading indicator but keep the previous results visible while fetching, rather than flashing an empty list. Cache results per query (SWR/TanStack Query or a small `Map`) so backspacing is instant. Handle empty states and errors separately. Keep the query in the URL so results are shareable and survive refresh. Support keyboard navigation and ARIA (`role='combobox'`, `aria-activedescendant`) for autocomplete. On the server, use an index suited to search (full-text or trigram) and a result limit.

</QA>

<QA q="How do you test a debounced search component?" level="senior">

Use fake timers (`vi.useFakeTimers()` or `jest.useFakeTimers()`), type into the input, and assert that no request happened before the delay and exactly one happened after advancing timers. Mock the API with MSW to control response timing, which lets you test the race condition too: delay the first response and verify the UI shows the result of the latest query.

</QA>
