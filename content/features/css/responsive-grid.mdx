## What it is

Card layouts (products, blog posts, dashboards) need 1 column on phones, 2 on tablets, 3–4 on desktop. The old way uses floats/flex with a media query per breakpoint. **CSS Grid with `auto-fill` + `minmax()`** figures out the column count automatically.

## Standard vs optimized

<CodeTabs>
<Tab label="Standard">

```css
/* ❌ Fixed breakpoints, margins math, breaks at in-between sizes */
.cards { display: flex; flex-wrap: wrap; margin: -8px; }
.card  { width: calc(100% - 16px); margin: 8px; }
@media (min-width: 640px)  { .card { width: calc(50% - 16px); } }
@media (min-width: 1024px) { .card { width: calc(33.333% - 16px); } }
@media (min-width: 1280px) { .card { width: calc(25% - 16px); } }
```

</Tab>
<Tab label="Optimized">

```css
/* ✅ As many columns as fit, each at least 260px, sharing leftover space */
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(min(260px, 100%), 1fr));
  gap: 1rem;
}
```

</Tab>
<Tab label="Tailwind">

```html
<!-- ✅ Same idea with an arbitrary value -->
<div class="grid gap-4 [grid-template-columns:repeat(auto-fill,minmax(min(260px,100%),1fr))]">
  <article class="rounded-xl border p-4">…</article>
</div>

<!-- or explicit breakpoints when you want exact control -->
<div class="grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4">…</div>
```

</Tab>
</CodeTabs>

<Callout type="why" title="Why it's better">
- **`auto-fill` + `minmax`** calculates columns from the available width, so it works at every size, not just your breakpoints.
- **`min(260px, 100%)`** prevents overflow on very narrow screens.
- **`gap`** replaces negative-margin hacks.
- It responds to the **container's** width, so the same grid works in a sidebar or full page.
</Callout>

## How to use

1. Pick a minimum card width (220–300px is typical).
2. Use `repeat(auto-fill, minmax(min(MIN, 100%), 1fr))`.
3. Use `auto-fit` instead of `auto-fill` if you want few items to **stretch** to fill the row.
4. For equal-height cards, make the card `display: flex; flex-direction: column` and push the footer with `margin-top: auto`.

## Use-case demos

### Use case 1: equal-height product cards with footer aligned

```html
<div class="cards">
  <article class="card">
    <img src="/p1.jpg" alt="" />
    <h3>Product name that might wrap to two lines</h3>
    <p class="price">$49</p>
    <button>Add to cart</button>
  </article>
</div>

<style>
  .card { display: flex; flex-direction: column; gap: .5rem; }
  .card img { aspect-ratio: 4 / 3; object-fit: cover; width: 100%; } /* no layout shift */
  .card button { margin-top: auto; } /* buttons line up across the row */
</style>
```

### Use case 2: card that changes layout based on its container (container queries)

```css
.card-wrap { container-type: inline-size; }

.card { display: grid; gap: 1rem; }

/* When the CARD (not the screen) is wider than 420px, go horizontal */
@container (min-width: 420px) {
  .card { grid-template-columns: 160px 1fr; }
}
```

### Use case 3: dashboard with a featured tile spanning 2 columns

```css
.dashboard { display: grid; grid-template-columns: repeat(auto-fill, minmax(240px, 1fr)); gap: 1rem; }
.tile--wide { grid-column: span 2; }
@media (max-width: 520px) { .tile--wide { grid-column: auto; } }
```

## Pitfalls & when not to use

<Callout type="warn" title="Watch out">
- `auto-fill` with very few items leaves empty tracks. Use `auto-fit` if you want them to stretch.
- `span 2` items can cause overflow on phones. Reset them at small sizes.
- Always set `aspect-ratio` on images to avoid layout shift (CLS).
</Callout>

## Interview questions

<QA q="Explain repeat(auto-fill, minmax(250px, 1fr))." level="junior">

`repeat(auto-fill, ...)` creates as many columns as fit in the container. `minmax(250px, 1fr)` says each column is at least 250px wide and otherwise shares the remaining space equally. Together, the grid shows four columns on a wide screen, then three, two and one as space shrinks, with no media queries. A common refinement is `minmax(min(250px, 100%), 1fr)` so a single column never overflows on very narrow screens.

</QA>

<QA q="What is the difference between auto-fill and auto-fit?" level="mid">

Both create as many tracks as fit. The difference shows when there are fewer items than tracks: `auto-fill` keeps the empty tracks, so items stay at their column width and leave space at the end; `auto-fit` collapses empty tracks to zero, so the existing items stretch to fill the row. Use `auto-fill` for consistent card sizes and `auto-fit` when a few items should fill the width.

</QA>

<QA q="CSS Grid vs Flexbox: when do you use which?" level="junior">

Flexbox is one-dimensional: it lays items out in a row **or** a column and is great for toolbars, nav bars and centering. Grid is two-dimensional: it controls rows **and** columns together, which suits page layouts and card grids where items should line up in both directions. A common rule: Flexbox for content-driven layouts inside components, Grid for layout-driven structure. They're often combined (a grid of cards, each card using flex inside).

</QA>

<QA q="What are container queries, and why are they useful for components?" level="mid">

Media queries respond to the **viewport** size; container queries respond to the size of a parent container. You mark a parent with `container-type: inline-size` and then use `@container (min-width: 400px)` rules for its children. That lets a card switch from stacked to side-by-side depending on where it's placed (sidebar vs main area), making components truly reusable. They're supported in all modern browsers.

</QA>

<QA q="How do you make cards in a row equal height with their buttons aligned at the bottom?" level="mid">

Grid rows already stretch items to the same height (`align-items: stretch` is the default). Inside each card, use `display: flex; flex-direction: column` and give the footer `margin-top: auto`, which pushes it to the bottom. For aligning internal parts (title, image, text) across cards in the same row, use `grid-template-rows: subgrid` on the card so it shares the parent grid's row tracks.

</QA>

<QA q="Images in the grid cause the page to jump while loading. Why, and how do you fix it?" level="mid">

Before an image loads, the browser doesn't know its height, so it reserves no space; when it arrives, content below shifts. That's Cumulative Layout Shift (CLS), a Core Web Vital. Set `width` and `height` attributes on `img` (modern browsers derive an aspect ratio from them) or use `aspect-ratio` in CSS plus `object-fit: cover`. `next/image` requires dimensions or a fill container for the same reason.

</QA>

<QA q="What accessibility issue can CSS Grid introduce?" level="senior">

Grid lets you visually reorder items with `order`, `grid-area`, or `grid-auto-flow: dense`, but screen readers and keyboard focus still follow the **DOM order**. If the visual order differs, keyboard users jump around unpredictably, which fails WCAG's meaningful sequence and focus order criteria. Keep the source order logical and use visual reordering only for decorative changes.

</QA>
